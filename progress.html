Waiting on you

Everything that can be built without you is built. These are the items only you can clear — each one is an account, a form or a decision, not code.

  • Nothing is blocking the build. Stages 0 to 5 are complete and the server runs end to end against live Bedrock. What follows is submission admin only.
  • Confirm the licence is visible in the repo’s About panel at Recall_Amazon. GitHub usually detects LICENSE automatically, but the rules require it visible there, so it is worth one look.
  • Create the public GitHub repo and confirm the MIT licence shows in the About panel. This is a hard submission requirement and it is worth zero points until a judge can see it.
  • Redeem the $150 promotional credits when the email lands — Billing → Credits → Redeem.
  • Decide the AWS Builder route before stage 4 ends. A single Bedrock call is what the judges name as the obvious answer; either build with Kiro Crew, which qualifies on its own, or give a second AWS service real work to do.
Not blocking: stage 4 can start without any of these. The grader prompt, the calibration fixture set and its scoring bands are all written and tested against recorded answers before a live model is ever called.

  2. Spike the risky links

    Days 1–3 · done 6 SepDone

    Prove the two things that could invalidate the plan, while pivoting is still cheap.

    • Confirm what Alexa+ Preview access a hackathon entrant actually gets — the MCP Toolkit is the documented path
    • Stand up a hello-world MCP server over Streamable HTTP — spike/hello_mcp.py
    • Connect from a real MCP client — fastmcp.Client and raw curl both handshake at protocol 2025-11-25; .mcp.json registers it for Claude Code

    • Made a live Bedrock call — ready, 1771 ms. Sonnet 5 is listed in the catalogue but refuses to invoke on a Free plan account, so the grader runs on Sonnet 4.5; Haiku 4.5 and Nova Lite also verified working.
    • Log every surprise in docs/FRICTION-LOG.md — four entries, two of them major
    Exit: a real MCP client gets a real response from a locally hosted server, and one Bedrock call has returned. Half met. The MCP half is proven end to end; the Bedrock half waits on credentials. The spike also cost the plan a new decision — Alexa+ enforces a sub-500 ms tool round trip, so grading had to be split into two calls (D7).

  3. Scheduler, test-first

    Days 4–8 · done 6 SepDone

    SM-2 as pure functions. Correctness matters most here and is cheapest to verify here, which is why it leads.

    • Tests for the 0–5 quality bands, written before the implementation and watched fail first
    • Ease-factor floor and the reset-on-failure path
    • Graded lapse — a 2 keeps 30% of the interval and its repetition history; 0 and 1 still reset. The 0–5 signal earning its keep twice.
    • Multi-month growth verified with an injected clock — intervals cross a year in ten perfect reviews, and a failing card never drifts past a week
    • review() and due_at() implemented, 23 tests green
    Exit met. pytest passes with no database and no wall clock anywhere in the suite.

  4. Store

    Days 9–13 · done 6 SepDone

    SQLite, one file, cards plus an append-only review log.

    • Schema for cards and reviews, with a pending-grade state for D7
    • Repository layer, integration-tested against real SQLite in a temp file — no mocks
    • Due-card query ordered by oldest debt first, with a session cap
    • submit_answer() provably leaves the schedule untouched until a grade lands (D6, D7)
    • Streak reconstruction from the review log, counting graded reviews only
    • Seeded demo deck — eight cards, idempotent so a second take does not double the pile
    Exit met. Cards survive a restart and the log reconstructs a streak. 41 tests green, lint clean.

  5. Grader on Bedrock

    Days 14–22 · done 7 SepDone

    The differentiator. Server-side semantic scoring of a spoken answer, plus the calibration evidence that it is fair.

    • Scoring prompt returning a 0–5 quality and one spoken sentence, at temperature=0
    • Calibration fixture set — 11 cases with score bands, 11 of 11 inside band on the first live run
    • Generated evidence in docs/CALIBRATION.md — readers judge the fairness themselves rather than trusting a green test
    • Degrades safely: Bedrock down, unparseable output or an off-scale score all return an unscored result and leave the schedule untouched
    • Empty or unintelligible transcript treated as “no answer”, and never reaches the model at all
    • AWS integration documented concretely in docs/PRODUCT-FEEDBACK.md
    Exit met. The case that matters: an answer whose key word was transcribed as “leemah” still scored 5, because the grader reads meaning rather than characters. That is the project's whole claim, demonstrated.

  6. MCP server and speech shaping

    Days 23–30 · done 7 SepDone

    Four tools wired to the domain modules, with every response written to be heard rather than read.

    • Five tools, not four — D7 split grading into submit_answer and get_grade. With add_card, next_due_card and get_streak_summary.
    • Response length caps and markup stripping, enforced by tests rather than by discipline
    • next_due_card returns one card and provably never speaks the answer with the question
    • Tool docstrings written for a model to read — they say when not to use a tool as well as when to
    • End-to-end run over real HTTP against live Bedrock: asked, answered in messy speech, graded on nuance, rescheduled, streak updated
    Exit met, with the number that matters: the answer was acknowledged in 18 ms against the Alexa+ 500 ms budget, while the 1054 ms grader ran behind it. D7 is not a workaround on paper — it measurably works.

  7. Browser voice harness

    Days 31–36 · done 7 SepDone

    Speech in and out via the Web Speech API against the same server. Insurance, usability test, and demo footage in one.

    • sim/index.html speaks real MCP over Streamable HTTP — a hand-written JSON-RPC client in the browser, verified in Chrome doing a live initialize (200), notifications/initialized (202) and two tools/call
    • Served from the MCP server’s own origin at /, so there is no CORS to configure and no second command for a judge to run
    • Web Speech API for microphone and voice; an empty transcript is passed through as “no answer” rather than swallowed
    • Shows the acknowledgement time beside each answer, so the D7 split is watched rather than described
    • Labelled SIMULATED Alexa+ experience at the top per the rules, with a test asserting the label is still there
    • Needs you: put headphones on and actually listen. Verbosity you can only hear is the one defect I cannot detect.
    Exit met in structure, not yet by ear. The browser drives a full cycle over real MCP; whether a whole review feels right spoken is the part that needs a human.
